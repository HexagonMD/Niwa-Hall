# とりっぴー — 共同旅行計画 Web アプリ

**HACK U 2025 発表作品**

---

## 概要

「旅行計画をみんなで作って、自分たちだけのしおりに仕上げる」共同編集型 Web アプリ。  
メンバー全員がリアルタイムで地図にピンを立て、スポットを追加・整理し、カスタマイズされた旅行しおりを出力できる。

編集データはサーバを経由せず WebRTC の P2P 通信でブラウザ間を直接流れるため、旅行計画のような個人情報を含むデータが外部サーバに残らない設計になっている。

- **イベント**：[HACK U](https://hacku.yahoo.co.jp/) — 2025年10月5日 発表
- **チーム規模**：4名
- **担当**：チームリーダー・WebRTC 実装・Google Maps API 連携

## 直面した課題と解決策

### 課題 1：WebRTC でのアプリ状態の同期漏れ

WebRTC P2P 接続確立後、後から接続したメンバーに既存のスポットデータが届かない問題が発生した。

- **原因**：初回接続時にアプリ状態のスナップショットを送る処理がなかった
- **解決**：接続確立イベント時に `appState` の全量を相手に送信する処理を追加（`app.js` の `appState` 同期ロジック）
- **結果**：新規参加者が既存データをリアルタイムで受け取れるようになった

### 課題 2：Google Maps のピン削除ボタンが機能しない

地図ピンのホバー時に表示される「閉じる」ボタンが正常に機能しなかった。

- **原因**：Google Maps の `InfoWindow` コンテンツは通常の DOM から切り離されており、イベントリスナーが機能しなかった
- **解決**：問題の閉じるボタン要素を削除し、Maps 標準のクローズ動作に統一することで一貫した UX を実現

### 課題 3：LAN 環境での WebRTC シグナリング

ハッカソン会場の Wi-Fi 環境で WebRTC の STUN/TURN が利用できないケースがあった。

- **解決**：Socket.IO を使ったシグナリングサーバをフォールバックとして実装し、WebRTC が確立できない場合でもリアルタイム同期が維持されるようにした

## アーキテクチャ概要

```
ブラウザ A ──WebRTC P2P──── ブラウザ B
    │                            │
    └──────── Socket.IO ─────────┘
                  │
            Node.js サーバ
         (シグナリング / フォールバック)
```

- 通常時：WebRTC P2P でブラウザ間直接通信（低遅延・編集データがサーバに残らない）
- フォールバック時：Socket.IO 経由でサーバ中継

---

## セットアップ

```bash
npm install
node server.js
```

ブラウザで `http://<サーバの IP>:3000` にアクセス。  
同一 LAN 内のデバイスから複数接続することで共同編集が開始できる。
